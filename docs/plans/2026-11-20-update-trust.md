# 可执行文件授信实施计划

目标：把系统设置的更新依据从单个正式版摘要改为跨版本、按发布平台匹配的双源授信清单。

1. 在 `apiServer/trust_manifest.py` 定义版本化 JSON 格式。三元组（版本、架构、SHA-256）去重，禁止按版本覆盖重构产物。
2. 在 apiServer 新增只读清单、专用密钥推送、SQLite 事务合并和中英文分页首页。已有 OAuth 配置不要求追补密钥，未配置时只关闭写入。
3. 扩展构建工作流，提取实际产物的摘要，非强制推送合并后的 `auth` 分支。竞争失败须取回新 HEAD 再合并。向服务端发送已提交的完整 JSON；Pages 同步部署这个仅含两份静态文件的分支。
4. 先检查 `TAO_UPDATE_SHA256`：与上传文件匹配则不联网。否则并发访问两个固定 HTTPS 地址，只按首份有效清单校验当前平台，不等待慢源；两者均失败则拒绝。保留暂存和启动回退。登记 APK 但不开放 Android 自更新。
5. 验证非法及陈旧推送、重构去重、部分构建、首个有效响应、取消慢请求、拒绝错误平台。运行独立 apiServer 测试、三组后端 CI 测试、前端测试和构建；核对 `auth` 分支树。
