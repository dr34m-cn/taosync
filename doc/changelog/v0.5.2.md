> [!CAUTION]
> **Android 端升级提示**：由于 Android 端环境特殊性以及本程序早期安卓端的设计缺陷，**v0.5.2 之前的 Android 版本在更新后会丢失 TaoSync 的配置数据**（从 v0.5.2 起已修复，后续版本可直接覆盖升级保留数据）。升级前请先做好备份；由于 Android 端存储隔离的特殊性，目前暂无便捷的自动备份方式，建议提前手动记录重要配置（如加密目录密钥、作业与存储设置等）。
>
> **请放心，更新不会影响或丢失你的网盘文件与本地文件**，仅会丢失 TaoSync 自身的配置数据。**Windows、macOS、Linux、Docker 等其他平台完全不受影响，可放心更新。**

## 🚀 特性

<details>
<summary><strong>在线自动更新程序</strong></summary>

Docker 与独立可执行文件部署现可在「系统设置 → 程序更新」中直接在线更新，无需手动下载安装包。默认选中置顶的「最新正式版」和「自动选择源」，也可手动切换当前平台可用的正式版或开发/测试版本，并选择下载源（正式版提供 GitHub Release 与 Cloudflare R2，非正式版提供 Cloudflare R2）。

自动选择源会并发测速并在首个可用源联通后立即取消其余探测；下载过程显示实时进度并支持中途取消。若所选版本与当前运行版本一致，界面会直接提示并阻止重复下载与更新。下载完成后自动按官方授信清单核对可执行文件与版本号，校验通过后自动重启并刷新页面，新程序启动失败时自动回退到上一版本。选择非正式版时会提示风险并要求二次确认。

原有上传更新区域调整为「手动更新」，并在 Docker 容器环境中补充防降级提醒：程序内更新在重启容器后保留，但重建容器会恢复为镜像自带版本，建议通过拉取新镜像升级。**从 v0.5.1 首次升级到 v0.5.2 仍需使用手动更新或原安装方式。**

</details>

<details>
<summary><strong>自动检测新版本提示</strong></summary>

打开「系统设置」页面时，TaoSync 会自动并发检查官方最新正式版。当检测到与当前运行版本不一致的新正式版时，页面顶部会显示更新提醒横幅，提供「前往下载」与快速跳转到「在线更新」的入口。离线或检测失败时静默处理，不影响正常使用设置页。

</details>

<details>
<summary><strong>挂载目录长期扫描缓存</strong></summary>

内置 TaoSync 引擎的每个挂载目录新增「扫描缓存保留天数」设置，默认 `30` 天；设为 `0` 表示关闭缓存并立即清除已有缓存，设为 `-1` 表示永不过期。

目录扫描缓存可跨作业和程序重启复用，命中时跳过远程存储列举请求与扫描间隔，减少重复查询；定期完整比对及全同步清理目标多余文件前仍会实时核对存储状态。同步期间新增、覆盖、删除或移动文件及目录时，仅更新受影响的缓存位置，不延长原有缓存有效期。外部直接修改目录内容需待缓存过期、禁用缓存或重新扫描后才能发现。

</details>

<details>
<summary><strong>自定义阿里云盘秒传门槛</strong></summary>

内置阿里云盘挂载开启「哈希秒传」后，可在开关右侧自定义尝试秒传的文件大小门槛，并支持选择 `KB`、`MB` 或 `GB` 单位，默认仍为 `10 MB`（旧配置沿用 `MB`）。

仅严格大于所设门槛的文件会尝试秒传，设为 `0` 时所有非空文件均可尝试。关闭开关后保留已填门槛值；单独修改开关或门槛不会清空目录扫描缓存或源目录快照。

</details>

<details>
<summary><strong>远程挂载目录浏览与新建</strong></summary>

配置内置引擎的 SMB、FTP 和 SFTP 挂载时，现已支持通过目录选择器浏览并选择根目录（SMB 直接连接目标共享，兼容隐藏共享及限制共享枚举的服务端）；默认从存储根目录 `/` 开始浏览，并支持一键切换为「从当前路径浏览」或「返回根目录」。

配置阿里云盘和加密目录挂载时，目录选择器现已支持直接新建并选中子目录（引擎根目录除外），与作业目录选择器保持一致。

</details>

<details>
<summary><strong>可选的匿名同步统计</strong></summary>

在「系统设置」中新增「匿名统计」开关（配置项 `anonymous_stats`），默认开启，可随时关闭且不影响同步，重新开启也不会补报历史数据。

每次任务完成后仅在后台异步发送两个数字：本次成功同步的文件数和总大小，不附带用户或设备标识，也不包含文件内容、文件名、路径或网盘信息。上报繁忙时跳过，失败不重试也不记日志，不影响任务结束与完成通知。官方授信页面将实时展示累计同步文件数和总体积（仅统计开启该选项的 v0.5.2 及以上版本；服务端仅保存累计总量，无法识别来源）。

</details>

<details>
<summary><strong>安卓端一键重置登录密码</strong></summary>

Android 客户端壳页面的日志工具栏新增「重置密码」按钮，忘记密码时无需查阅密钥文件，点击即可立即生成新的随机密码并展示当前账号与新密码，点击密码或「复制」按钮可直接复制到剪贴板，同时自动清除登录错误锁定。

该入口仅限 TaoSync 应用内置壳页面访问，已拦截同机其他应用、外部浏览器及跨站内嵌调用，且日志不会记录敏感令牌或明文密码。

</details>

## 🎨 优化

<details>
<summary><strong>加快阿里云盘递归扫描</strong></summary>

内置阿里云盘递归扫描目录时，会直接复用本轮已获取的子目录 ID，减少重复的路径解析与云端查询请求。

</details>

<details>
<summary><strong>拆分授信清单并加快更新校验</strong></summary>

官方授信服务与 GitHub Pages 将正式版（`auth.json`）、非正式版（`auth-dev.json`）和最新正式版（`latest.json`）独立输出，授信页面默认仅加载正式版，切换「展示全部版本」时再按需加载非正式版。

手动上传更新包校验时，程序优先并发读取两个官方站点的最新正式版清单并关闭较慢一方；未命中时再从先响应的站点依次校验完整正式版与非正式版清单，减少常见升级的等待时间。

</details>

<details>
<summary><strong>固定安卓包签名并支持覆盖升级保留数据</strong> <a href="https://github.com/dr34m-cn/taosync/issues/246">#246</a></summary>

从 v0.5.2 起，官方发布的 Android 安装包改用固定签名密钥，并将运行数据目录移出更新时会被清空的程序解包目录，迁至持久化私有数据目录。后续新版本可直接覆盖安装升级并完整保留数据库、密钥、作业与设置，不再提示签名不一致或丢失数据。**若设备当前安装的是 v0.5.1 或更早版本，由于旧版签名不同且数据位于解包目录内，升级到 v0.5.2 时仍需先备份必要信息并卸载旧版后重新安装。**

</details>

<details>
<summary><strong>修改非存储挂载项保留源快照</strong></summary>

编辑内置存储挂载目录时，若仅调整并行复制数、扫描缓存保留天数、秒传设置等非存储位置相关项且未改变启用状态，不再误清空该引擎下作业的源目录快照，避免触发不必要的全量重新扫描。

</details>

<details>
<summary><strong>优化设置页布局与秒传体积单位</strong></summary>

系统设置中的通用 API 秘钥与执行作业专用秘钥合并展示在同一「API 秘钥」区域，布局更清晰紧凑；任务历史统计中的阿里云盘秒传体积改用自适应单位显示，不再固定以 `GB` 显示导致较小体积显示为 `0.00 GB`。

</details>

## 🚀 Features

<details>
<summary><strong>Update online from System Settings</strong></summary>

For Docker and standalone deployments, **System Settings → Program update** now supports updating directly online without downloading packages manually. It defaults to the pinned **Latest official release** and **Auto-select source**, while also letting you pick other available official or development/prerelease builds for your platform and switch download sources (official releases offer GitHub Release and Cloudflare R2; non-official builds offer Cloudflare R2).

Auto-select tests download sources in parallel and cancels remaining probes as soon as the first reachable source responds. Downloads show live progress and can be canceled mid-transfer. If the selected version matches the currently running version, TaoSync notes this and prevents redundant downloading and updating. After downloading, TaoSync verifies the executable and version against the official trusted build registry, restarts automatically, and reloads the page, rolling back to the previous version if the new executable fails to start. Selecting a non-official build displays an extra risk warning and confirmation prompt.

The previous upload area is now labeled **Manual update**. In Docker containers, an explicit alert notes that in-app updates survive container restarts, whereas recreating the container reverts to the image version and may downgrade TaoSync; updating by pulling a newer Docker image is recommended. **To upgrade from v0.5.1 to v0.5.2 for the first time, use manual update or your original installation method.**

</details>

<details>
<summary><strong>Check for new releases automatically</strong></summary>

Opening **System Settings** automatically checks both official registry endpoints in parallel for the latest official release. When a newer official release differs from the running version, a banner appears at the top of the page with quick links to **Download release** or jump directly to **Program update**. Offline or failed checks fail silently without blocking settings.

</details>

<details>
<summary><strong>Persistent directory scan cache per mount</strong></summary>

Each mount in the built-in TaoSync engine now includes a **Directory scan cache (days)** setting, defaulting to `30` days. Set it to `0` to disable caching and immediately clear existing cached entries, or `-1` so cached entries never expire.

Cached directory listings persist across jobs and restarts. Cache hits skip remote listing requests and scan intervals to cut redundant queries, while scheduled full comparisons and full-sync mirror deletions still verify live storage before acting. Creating, overwriting, deleting, or moving files or folders updates only affected cached paths without extending the original expiration time. External modifications outside TaoSync require cache expiration, disabling the cache, or a fresh scan to be detected.

</details>

<details>
<summary><strong>Configure Aliyun Drive rapid upload threshold</strong></summary>

When **Hash-based Rapid Upload** is enabled on a built-in Aliyun Drive mount, you can configure the file-size threshold directly beside the toggle and choose `KB`, `MB`, or `GB` units. The default remains `10 MB`, and existing configurations continue to use `MB`.

Only files strictly larger than the threshold attempt rapid upload; setting `0` enables rapid upload attempts for all non-empty files. Disabling the toggle preserves the saved threshold value, and changing only the toggle or threshold does not clear the directory scan cache or source snapshots.

</details>

<details>
<summary><strong>Browse and create folders in mount pickers</strong></summary>

When configuring built-in SMB, FTP, and SFTP mounts, you can now browse and select the root directory with the folder picker (SMB connects directly to the target share, supporting hidden shares and servers that restrict share enumeration). It opens at the storage root `/` by default and provides one-click toggles to **Browse from current path** or go **Back to root**.

When configuring Aliyun Drive and encrypted directory mounts, the folder picker now supports creating and selecting subdirectories in place (except at the synthetic engine root), matching the job directory picker.

</details>

<details>
<summary><strong>Optional anonymous sync statistics</strong></summary>

Added an **Anonymous statistics** toggle (`anonymous_stats`) in **System Settings**. It is enabled by default, can be turned off at any time without affecting synchronization, and re-enabling it does not backfill historical runs.

After each run, TaoSync asynchronously reports only two numbers in the background: how many files synced successfully and their total byte size. No user or device identifiers, file contents, filenames, paths, or cloud drive details are sent. Reporting skips when busy, never retries or logs errors on failure, and never delays task completion or notifications. The official trusted build registry page displays live cumulative totals for files synced and total volume (covering TaoSync v0.5.2 and later with statistics enabled; the server stores only cumulative totals and cannot identify sources).

</details>

<details>
<summary><strong>One-tap password reset on Android</strong></summary>

Added a **Reset Password** button to the Android shell log toolbar. When you forget your password, tapping it immediately generates a new random password without looking up `secret.key`, displays the current username and new password with one-tap copy, and clears any login error lockout.

This action is restricted to TaoSync's built-in Android shell WebView, blocking other apps on the same device, external browsers, and cross-site framing, while keeping tokens and plaintext passwords out of logs.

</details>

## 🎨 Improvements

<details>
<summary><strong>Faster Aliyun Drive recursive scans</strong></summary>

Recursive scans on built-in Aliyun Drive mounts now reuse subfolder IDs already discovered during the same scan pass, reducing repeated path resolution and cloud API queries.

</details>

<details>
<summary><strong>Split trusted manifests and faster verification</strong></summary>

The official registry service and GitHub Pages now publish separate manifests for official releases (`auth.json`), non-official builds (`auth-dev.json`), and the latest official release (`latest.json`). The registry page loads official releases by default and loads non-official builds on demand when switching to **Show all versions**.

When verifying a manually uploaded update package, TaoSync queries the latest official release manifest from both official endpoints concurrently and cancels the slower request; if unmatched, it falls back sequentially to the full official and non-official manifests on the faster endpoint, shortening wait times for common upgrades.

</details>

<details>
<summary><strong>Preserve Android data across direct APK upgrades</strong> <a href="https://github.com/dr34m-cn/taosync/issues/246">#246</a></summary>

Starting with v0.5.2, official Android APKs use a fixed signing key and store runtime data in a persistent private directory outside the app unpack directory that gets wiped on upgrades. Future releases can install directly over v0.5.2 while preserving databases, keys, jobs, and settings without signature-mismatch errors or data loss. **If you currently have v0.5.1 or earlier installed, back up any needed data and uninstall the older version before installing v0.5.2 because earlier builds used different signing keys and stored data inside the unpack directory.**

</details>

<details>
<summary><strong>Preserve source snapshots on non-storage mount edits</strong></summary>

Editing non-storage settings on a built-in mount—such as copy concurrency, scan cache retention days, or rapid upload options—without changing the backing storage location or enabled state no longer clears source snapshots for jobs on that engine, avoiding unnecessary full rescans.

</details>

<details>
<summary><strong>Refined Settings layout and rapid upload size units</strong></summary>

Combined the general API key and job execution key under a single **API keys** section in System Settings for a cleaner layout. Rapid upload volume in task history statistics now formats with adaptive size units instead of always displaying in `GB` (which previously showed small totals as `0.00 GB`).

</details>
