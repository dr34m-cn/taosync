## 须知

> [!IMPORTANT]
> 内置 TaoSync 引擎目前为**测试版**，可直接连接本地目录、SMB、FTP、SFTP 和阿里云盘，无需部署 OpenList。**目前仍推荐使用 OpenList/AList 等外部引擎**；请另行部署 [OpenList](https://docs.oplist.org/)/AList 并添加外部引擎。

> [!WARNING]
> **警告！不要在外网暴露本系统，否则后果自负！**
>
> 本系统已经做了一定的安全方面的工作，但仍不能保证绝对安全。如确实需要，请务必使用强密码，并使用`SSL`

## 用途举例

#### 1. 同步备份

把本地文件备份到多个网盘或FTP之类的存储，或者在多个网盘之间同步文件等；

可以定时扫描指定目录下的文件差异。仅新增模式会复制目标中缺失或大小不同的文件，保留目标端多余内容；全同步模式还会按排除和文件大小过滤规则清理目标端多余内容。

#### 2. 定时下载

可以设置一次性任务（`cron`方式设置年月日时分秒，将在指定时间执行一次），可在闲时自动从特定网盘下载文件到本地

## 特性

* 开源免费，接受任意审查，几乎支持所有常用平台
  * windows-amd64
  * windows-arm64
  * darwin-amd64
  * darwin-arm64
  * linux-amd64
  * linux-arm64
  * linux-386
  * linux-arm-v6
  * linux-arm-v7
  * linux-s390x
  * linux-ppc64le
  * Android
* [Github Actions](https://docs.github.com/zh/actions)自动打包与发布构建好的可执行程序，过程公开透明，无投毒风险
* 支持Docker，下载即用
* 适配PC&移动端显示，方便易用
* 干净卸载，不用的时候删掉即可，无任何残留或依赖，不影响系统里其他程序
* 数据库内的登录密码以 PBKDF2 加盐散列保存，支持重置密码；如通过配置文件或环境变量设置初始密码，请妥善保护相关配置
* 服务在本地运行，按配置连接存储、外部引擎和通知服务；阿里云盘扫码授权与令牌刷新会连接授权服务，文件传输直接连接阿里云盘
* 完善的错误处理，稳定可靠，逻辑自洽；可能出错，但永不崩溃（我猜的）
* 完善的日志，所有错误都会被记录
* 内置 TaoSync 引擎支持本地目录、SMB、FTP、SFTP 和阿里云盘，也可管理外部 `OpenList/AList` 引擎
* 作业管理支持新增、删除、启用、禁用、编辑和手动执行；提供上次执行摘要及桌面端批量操作
* 支持排除项规则，可以排除指定目录或文件不同步
* 支持按文件大小过滤，可分别设置最小和最大值
* 仅新增、全同步、移动三种模式
* 源目录模式通过快照减少目标扫描，逐文件保存完成进度，支持中止或重启后继续同步
* 支持设置并行复制数，按目标存储目录或外部引擎共享额度
* 定时同步支持间隔、`cron`、手动调用
* 同步进度、总体进度、同步速度、实时同步文件、预估时间等实时可视化查看
* 存储可控，合理配置任务记录与日志保留天数，可以控制本程序所占用存储在可控范围内
* 支持钉钉群机器人、Server酱、企业微信应用消息、Lark 群机器人、Bark、pushPlus、PushDeer 和自定义通知；高级自定义通知支持请求头、请求体及 `$title`、`$content` 变量

## 使用方法

### 先启动

* 可执行程序

前往[Release](https://github.com/dr34m-cn/taosync/releases)下载对应平台的可执行程序，直接执行

* docker

```sh
docker run -d --restart=always -p 8023:8023 -v /opt/data:/app/data --name=taoSync dr34m/tao-sync:latest
```

或docker-compose

```yaml
version: '3.8'

services:
  tao-sync:
    image: dr34m/tao-sync:latest
    container_name: taoSync
    restart: always
    ports:
      - "8023:8023"
    volumes:
      - /opt/data:/app/data
```

把其中`/opt/data`替换为你实际的目录，在部分NAS(如绿联NAS)中，可以使用相对目录，如`./config:/app/data`

使用内置引擎同步宿主机文件时，还需挂载对应目录，例如增加 `-v /mnt/photos:/storage/photos`，再在 TaoSync 中选择容器内的 `/storage/photos`；Compose 中可在 `volumes` 下增加同样的路径映射。

#### 与 OpenList 一起部署的 Docker Compose

使用以下 Compose 配置可以同时启动 TaoSync 和 OpenList：

```yaml
services:
  openlist:
    image: openlistteam/openlist:latest
    container_name: openlist
    user: "0:0"
    restart: unless-stopped
    ports:
      - "5244:5244"
    environment:
      UMASK: "022"
      TZ: Asia/Shanghai
    volumes:
      - ./openlist-data:/opt/openlist/data

  tao-sync:
    image: dr34m/tao-sync:latest
    container_name: taoSync
    restart: unless-stopped
    depends_on:
      - openlist
    ports:
      - "8023:8023"
    volumes:
      - ./taosync-data:/app/data
```

启动后，可通过 `http://127.0.0.1:5244` 访问 OpenList，通过 `http://127.0.0.1:8023` 访问 TaoSync。在 TaoSync 中添加引擎时，OpenList 地址应填写 `http://openlist:5244`；Compose 网络内可以直接使用服务名作为主机名。

当前 OpenList 镜像已不再使用 `PUID` 和 `PGID` 环境变量。此示例使用 `user: "0:0"` 以获得较广泛的兼容性；如需按最小权限运行，请将其替换为用于运行 OpenList 的宿主机 UID/GID，并确保该用户对 `./openlist-data` 具有写权限。详情请参阅 [OpenList Docker 文档](https://doc.oplist.org/guide/installation/docker)。

### 再使用

访问`http://127.0.0.1:8023`

默认账号为`admin`。当初始密码配置为`RANDOM`时，密码请到日志中查看；如果手动配置了密码，请直接使用该值登录。登录后请立即通过用户菜单修改密码，也可在该菜单修改用户名。

> [!NOTE]
> 如果没有显示这个日志，可以到同级目录的`data/log/sys_xxx.log`文件查看，通常在第一行

进入系统后，在`引擎管理`中选择内置 TaoSync 引擎，打开目录管理并添加存储目录；也可添加外部 OpenList/AList 引擎。随后前往`作业管理`创建同步作业。一个作业的源目录与所有目标目录须属于同一引擎。

### 内置存储与并发设置

* 本地目录选择 TaoSync 进程可访问的路径；SMB 支持发现设备、选择共享或手动填写；SFTP 支持密码和密钥认证。
* 阿里云盘默认通过公共授权服务扫码登录，也可使用 **[自建授权服务](./apiServer/README.md)（更推荐，安全性更高）** 或自行配置应用凭据。支持目录选择、云端重命名和移动；小于 100 MiB 的文件直接上传，较大文件尝试哈希秒传。
* 并行复制数默认 5，范围 1～100。内置引擎在目录管理中按目标存储目录设置，外部 OpenList/AList 在引擎设置中配置；多个作业共享对应额度。

### 同步行为

源目录模式首次运行完整比对目标，此后通过源快照判断变化，并默认每 15 天在作业执行时重新完整比对。变化检测依赖存储提供的哈希、修改时间等元数据，不保证识别元数据未变化的同大小文件修改。每个文件在所有目标完成后保存进度，失败文件在后续执行中继续重试。

若希望目标端手动删除的文件不再补传，可使用“仅新增 + 源目录模式”，完成首次同步后将完整比对周期设为 0。此行为适用于源文件未变化的情况；源文件变化仍会触发同步，修改作业导致快照重建时也会重新比对。

移动模式会在所有目标复制成功、重新确认大小一致且源文件未变化后删除源文件，并清理本次移空的源子目录。全同步遇到源根目录为空而目标仍有内容，或源快照从非空变为空时，会触发空源保护并记为失败；如需清空目标，请手动处理。定时作业编辑前须先禁用，并等待正在执行的任务结束。

### 从旧版升级

升级前备份完整 `data` 目录。升级后需重新登录；旧密码在成功登录时自动升级为 PBKDF2 散列，升级后的数据库不支持直接降级到旧版。如需回退，请同时恢复升级前的程序和数据备份。

## 配置项

<details>
<summary>点击展开配置项</summary>

配置按每个选项应用优先级：`data/config.ini` > `环境变量` > `默认值`。文件中缺失的选项仍读取环境变量；无效的数值配置会记录错误并保留已读取的较低优先级值。手动修改配置文件或环境变量后需重启程序或容器。

系统设置可在线修改任务记录保留时间、任务超时、源目录完整比对周期和阿里云盘授权服务地址，保存后无需重启，并将这四项当前值写入 `data/config.ini`。后续启动时，这些已保存的值优先于环境变量。

`data/config.ini`文件示例（如该文件存在，则**优先级最高**）

```ini
[tao]
# 初始管理员密码，仅首次创建数据库时生效；RANDOM或空值表示随机生成
password=RANDOM
# 运行端口号
port=8023
# 登录有效期，单位天
expires=2
# 日志等级：0-DEBUG，1-INFO，2-WARNING，3-ERROR，4-CRITICAL；数值越大，产生的日志越少，推荐1或2
log_level=1
# 控制台日志等级：适用于v0.2.3及之后版本，与上同
console_level=2
# 系统日志保留天数，该天数之前的日志会自动清理，单位天，0表示不自动清理
log_save=7
# 任务记录保留天数，该天数之前的记录会自动清理，单位天，0表示不自动清理
task_save=0
# 任务执行超时时间，单位小时，0表示不限制；为大批量备份预留足够时间
task_timeout=72
# 源目录模式的完整比对周期，单位天，可用小数；0关闭定期比对，首次仍完整比对
source_full_scan_days=15
# 阿里云盘扫码授权和令牌刷新服务地址
aliyun_auth_server=https://taoapi.dr34m.cn
```

首次启动不要求存在此文件。可在程序工作目录的 `data` 下创建 UTF-8 编码的 `config.ini`，或通过系统设置自动生成；Docker 内路径为 `/app/data/config.ini`。

`aliyun_auth_server` 用于阿里云盘扫码授权及令牌刷新，可填写 **自建授权服务（更推荐，安全性更高）** 的 HTTPS 地址。配置文件中省略该项或留空时沿用 `TAO_ALIYUN_AUTH_SERVER`；环境变量也未设置或为空时，使用 `https://taoapi.dr34m.cn`。在线设置需填写完整地址；切换授权服务后，应重新为相关阿里云盘目录扫码授权。

超时也支持 `timeout`，在线设置使用此键保存；若文件中同时存在 `task_timeout` 和 `timeout`，前者优先。完整比对周期兼容旧的 `source_full_scan_hours` / `TAO_SOURCE_FULL_SCAN_HOURS`（小时），同一来源优先使用新的天数配置。`password` 留空仍表示随机密码，不会沿用环境变量中的密码。
