## Before You Begin

> [!IMPORTANT]
> The built-in TaoSync engine is currently in **Beta** and connects directly to local directories, SMB, FTP, SFTP, and Aliyun Drive without OpenList. **External engines such as OpenList/AList are still recommended**; deploy [OpenList](https://docs.oplist.org/)/AList separately and add it as an external engine.

> [!WARNING]
> **Do not expose TaoSync directly to the public internet. You do so at your own risk!**
>
> If you need remote access, use a strong password and enable HTTPS in System Settings or on your reverse proxy.

## Use Cases

#### 1. Synchronized Backups

Back up local files to multiple cloud drives, FTP servers, or similar storage services, or synchronize files between multiple cloud drives.

TaoSync can scan directories on a schedule. Add only mode copies missing files, updates files when it detects changes, and keeps extra files at the destination. Full sync also removes extra destination content according to the job’s exclusion and file-size rules.

#### 2. Scheduled Downloads

You can create a one-time job by specifying the year, month, day, hour, minute, and second using `cron`. This lets TaoSync automatically download files from a specific cloud drive to local storage during off-peak hours.

## Features

* Free and open source, open to public review, and available on virtually all common platforms
  * windows-amd64
  * windows-arm64
  * darwin-amd64
  * darwin-arm64
  * linux-amd64
  * linux-arm64
  * linux-386
  * linux-arm-v6
  * linux-arm-v7
  * linux-s390x
  * linux-ppc64le
  * Android
* Executables are automatically built and released through [GitHub Actions](https://docs.github.com/en/actions), making the entire build process public and transparent and minimizing the risk of tampered builds
* Ready-to-use Docker image
* Responsive interface for both desktop and mobile devices
* Clean removal: simply delete TaoSync when you no longer need it; it leaves no residual files or dependencies and does not affect other applications
* Login passwords are stored in the database as salted PBKDF2 hashes, and password resets are supported. If you set the initial password through a configuration file or environment variable, protect that configuration carefully
* Runs locally and connects to configured storage, external engines, and notification services. Aliyun Drive QR authorization and token refresh use an authorization service; file transfers connect directly to Aliyun Drive
* Comprehensive error handling for stable, reliable, and internally consistent operation. Errors may happen, but crashes never do (or so I think)
* Detailed logging: all errors are recorded
* The built-in TaoSync engine supports local directories, SMB, FTP, SFTP, and Aliyun Drive; external `OpenList/AList` engines can also be managed
* The job list shows each job’s last result and transfer totals. Create, delete, enable, disable, edit, or manually run jobs. You can edit an enabled job while it is idle. Bulk actions are available on desktop
* Exclusion rules for preventing specified directories or files from being synchronized
* File-size filtering with independently configurable minimum and maximum values
* Three synchronization modes: Add only, Full sync, and Move mode
* Source directory mode reduces destination scans through snapshots, saves completed progress per file, and resumes synchronization after interruption or restart
* Configurable concurrent copies, with a shared limit per destination storage directory or external engine
* Run jobs on an interval or `cron` schedule, manually, or through the API. Use **Job links** to start one or more follow-up jobs immediately or after a delay, either on completion or only when the first job succeeds without failures
* Real-time visualization of per-file progress, overall progress, synchronization speed, the file currently being synchronized, estimated completion time, and more
* Task history shows how long each run took and the counts and sizes of copies, moves, deletions, and failures. Retry one failed file from task details, or retry all failures from task details or history statistics. Retries skip the directory scan and preserve the original errors. They do not send notifications or trigger linked jobs
* Controllable storage usage: configure retention periods for task records and logs to keep TaoSync's storage footprint within a predictable range
* Notifications through DingTalk group bots, ServerChan, WeCom application messages, Lark group bots, Bark, pushPlus, PushDeer, and custom requests. Each channel supports failure-only notifications and recipient notes. Advanced custom notifications support headers, request bodies, and the `$title` and `$content` variables

## Usage

### Start TaoSync

* Standalone executable

Download the executable for your platform from [Releases](https://github.com/dr34m-cn/taosync/releases) and run it directly.

* Docker

```sh
docker run -d --restart=always -p 8023:8023 -v /opt/data:/app/data --name=taoSync dr34m/tao-sync:latest
```

Or use Docker Compose:

```yaml
version: '3.8'

services:
  tao-sync:
    image: dr34m/tao-sync:latest
    container_name: taoSync
    restart: always
    ports:
      - "8023:8023"
    volumes:
      - /opt/data:/app/data
```

Replace `/opt/data` with the directory you want to use. On some NAS devices, such as UGREEN NAS, you can use a relative path, for example `./config:/app/data`.

To synchronize host files with the built-in engine, also mount the relevant directory, for example with `-v /mnt/photos:/storage/photos`, then select `/storage/photos` inside TaoSync. For Compose, add the same mapping under `volumes`.

#### Docker Compose with OpenList

Use the following Compose file to start TaoSync and OpenList together:

```yaml
services:
  openlist:
    image: openlistteam/openlist:latest
    container_name: openlist
    user: "0:0"
    restart: unless-stopped
    ports:
      - "5244:5244"
    environment:
      UMASK: "022"
      TZ: Asia/Shanghai
    volumes:
      - ./openlist-data:/opt/openlist/data

  tao-sync:
    image: dr34m/tao-sync:latest
    container_name: taoSync
    restart: unless-stopped
    depends_on:
      - openlist
    ports:
      - "8023:8023"
    volumes:
      - ./taosync-data:/app/data
```

After startup, open OpenList at `http://127.0.0.1:5244` and TaoSync at `http://127.0.0.1:8023`. When adding the engine in TaoSync, use `http://openlist:5244` as the OpenList URL. The service name works as the hostname inside the Compose network.

Current OpenList images no longer use the `PUID` and `PGID` environment variables. This example uses `user: "0:0"` for broad compatibility; for least-privilege operation, replace it with the host UID/GID that should run OpenList and ensure that user can write to `./openlist-data`. See the [OpenList Docker documentation](https://doc.oplist.org/guide/installation/docker) for details.

### Use TaoSync

Open `http://127.0.0.1:8023`.

The default username is `admin`. If the initial password is configured as `RANDOM`, find the generated password in the logs. If you configured a password manually, use that value to sign in. After signing in, change the password immediately through the user menu, which also lets you change your username.

> [!NOTE]
> If the password does not appear in the console output, check `data/log/sys_xxx.log` in the same directory. It is usually on the first line.

After signing in, open **Engine Management**. Select the built-in TaoSync engine and add storage under **Directory Management**, or add an external OpenList/AList engine. Then create a job in **Job Management**. Its source and destinations must belong to the same engine. No two paths may be identical or contain one another. Adjust any overlapping destinations in existing jobs before running or retrying them.

You can create subdirectories directly in the source and destination pickers, except at the engine root. To keep the source directory name at the destination, create and select a destination subdirectory with that name.

### Built-in Storage and Concurrency

* For local storage, select a path accessible to the TaoSync process. Its program and runtime data directories are protected. SMB supports device discovery, share selection, and manual entry. SFTP supports password and key authentication.
* Aliyun Drive uses QR authorization through the public service by default. You can also use a **[self-hosted authorization service](./apiServer/README.md) (preferred for greater security)** or supply your own application credentials. It supports directory selection and cloud renames and moves. When rapid upload is enabled, TaoSync attempts it only for files larger than 10 MiB. You can filter successful rapid uploads in task details and see their count and size in task history.
* Concurrent copies default to 5, with a range of 1 to 100. For the built-in engine, configure each destination storage directory in directory management. For OpenList/AList, configure the external engine. Jobs share the corresponding limit.

### Encrypted Backups and Recovery

In the built-in engine’s **Directory Management**, add an **Encrypted Directory**. Select a dedicated backup folder on an existing storage mount, set an encryption key, and choose whether to encrypt directory names. Save it and select the encrypted directory as your job’s destination. TaoSync encrypts file contents and filenames on write. Existing plaintext files stay as they are. To restore, use the encrypted directory as the source and copy to a regular directory to recover the original names and contents.

**Back up the encryption key separately. If you lose both the key and the TaoSync database, you cannot decrypt the backup.** Saving locks the key, the underlying path, and the directory-name encryption setting. When migrating the underlying backup, copy the entire directory, including the companion name records for long file and directory names.

### Synchronization Behavior

Source directory mode compares against the destination on the first run, then detects changes through source snapshots. By default, it performs another full comparison during a job run every 15 days. Change detection relies on storage metadata such as hashes and modification times; it cannot guarantee detection of same-size changes when that metadata stays unchanged. Progress is saved for each file after all destinations complete, and failed files are retried on subsequent runs.

When comparing files with the same name at the source and destination, TaoSync can detect different contents at the same size if both sides already provide trusted whole-file hashes using the same algorithm, such as SHA-1 from the built-in Aliyun Drive mount. Otherwise, TaoSync compares sizes without reading the files to compute a hash. OpenList/AList hashes are used only to detect changes at the same source path, so differences between providers do not cause repeated transfers.

To avoid restoring files you manually delete from the destination, use Add only with Source directory mode and set the full comparison interval to 0 after the first successful synchronization. This applies while the source file remains unchanged. Source changes still trigger synchronization, and job changes that reset the snapshot trigger a new comparison.

Before deleting each source file in Move mode, TaoSync rechecks every destination copy, then verifies that the source has not changed since the scan. If verification fails, it keeps the source file. It also removes source subdirectories emptied by that run.

Full sync preserves excluded files even inside directories found only at the destination. It reports a failure and activates empty-source protection when the source root is empty but the destination still has content, or when a previously nonempty source snapshot becomes empty. Clear the destination manually if that is your intention.

### HTTPS and API Keys

In **System Settings**, upload or paste a PEM certificate chain and its unencrypted PEM private key to enable HTTPS or replace a certificate. HTTPS defaults to port `8025`. You can choose another port except the current HTTP port or the reserved port `8024`. To use the default HTTPS port in Docker, add `-p 8025:8025` to `docker run` or add `"8025:8025"` under `ports` in Compose. Open the HTTPS address matching your certificate and sign in separately. Disabling HTTPS keeps the certificate and key for reuse.

To trigger syncs from a script, generate a **Job execution key** in **System Settings** and send it in the `Authorization` header. It can start one job by ID or start all jobs. Find the ID in the job list. The **General API key** grants administrator access. Both keys are disabled by default and shown only when generated. Resetting or disabling a key immediately invalidates its previous value. [curl example](./web/src/views/pages/setting/api-key.en.md)

### Upgrading from Older Versions

Back up the entire `data` directory before upgrading. **For your first upgrade from v0.5.0 or earlier to v0.5.1, use your original installation method.** For Docker, pull the new image and recreate the container with the original data volume. For a standalone installation, stop TaoSync and replace the executable. When upgrading from a version before v0.5.0, sign in again to migrate the old password hash to PBKDF2. To downgrade, restore both the old program and the data backup made before upgrading.

Starting with v0.5.1, Docker and standalone installations show their build target under **System Settings → Program update**. Download the matching executable, ZIP, or tar.gz archive from GitHub Releases. Once sync jobs have finished, drop the file onto the page and confirm. TaoSync verifies the platform and the executable’s SHA-256 against the official trusted build registry before restarting. If the new program fails to start, TaoSync restores the previous version. In Docker, a page-installed update survives a container restart. Recreating the container uses the version in the selected image. For source and mobile installations, keep using the original update method.

## Configuration

<details>
<summary>Click to view configuration options</summary>

Configuration precedence applies to each option: `data/config.ini` > `environment variables` > `default values`. Options absent from the file still use environment variables. Invalid numeric settings are logged and retain the lower-priority value already loaded. Restart TaoSync or its container after manually changing configuration files or environment variables.

System Settings lets you edit task record retention, task timeout, the source directory full comparison interval, and the Aliyun Drive authorization service URL without restarting. Saving writes the current values of all four settings to `data/config.ini`; these saved values take precedence over environment variables on subsequent starts.

Example `data/config.ini` file (when present, this file has the **highest priority**):

```ini
[tao]
# Initial administrator password; only used when the database is first created.
# RANDOM or an empty value generates a random password.
password=RANDOM
# HTTP listening port
port=8023
# Login session lifetime in days
expires=2
# Log level: 0-DEBUG, 1-INFO, 2-WARNING, 3-ERROR, 4-CRITICAL.
# Higher values produce fewer logs; 1 or 2 is recommended.
log_level=1
# Console log level; available in v0.2.3 and later. Uses the same levels as above.
console_level=2
# System log retention period in days. Older logs are removed automatically; 0 disables automatic cleanup.
log_save=7
# Task record retention period in days. Older records are removed automatically; 0 disables automatic cleanup.
task_save=0
# Task execution timeout in hours; 0 disables it. Allow enough time for large backups.
task_timeout=72
# Full comparison interval for Source directory mode, in days; fractions are allowed.
# 0 disables periodic comparisons, but the first run still performs a full comparison.
source_full_scan_days=15
# Aliyun Drive QR authorization and token refresh service URL.
aliyun_auth_server=https://taoapi.dr34m.cn
```

This file is not required on first startup. Create a UTF-8 `config.ini` under `data` in the program's working directory, or let System Settings create it. Inside Docker, the path is `/app/data/config.ini`.

`aliyun_auth_server` configures Aliyun Drive QR authorization and token refresh and accepts the HTTPS URL of a **self-hosted authorization service (preferred for greater security)**. If the file omits this option or leaves it empty, it retains `TAO_ALIYUN_AUTH_SERVER`. If that environment variable is also unset or empty, it uses `https://taoapi.dr34m.cn`. System Settings requires a complete URL. After switching authorization services, authorize the affected Aliyun Drive directories again.

The timeout also accepts `timeout`, which is the key saved by System Settings. If the file contains both `task_timeout` and `timeout`, `task_timeout` takes precedence. The full comparison interval still accepts legacy `source_full_scan_hours` / `TAO_SOURCE_FULL_SCAN_HOURS` values in hours; within each configuration source, the new days option takes precedence. An empty `password` means a random password and does not retain a password from the environment.
